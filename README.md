# CodeArt

Блоки-полотна для Minecraft 1.7.10, картинки для которых задаёт сервер. Клиент ничего не хранит заранее:
при входе он получает манифест артов, тянет байты по своему каналу и кэширует их на диске по sha256.
Поставил полотно, кликнул по грани блока, на стене картина.

Реестр артов лежит в `config/code/art/arts.json`: имя, размер полотна в блоках и источник. Источник это
файл из `config/code/art/images` (`local://posters/sunset.png`) или адрес http(s), который сервер
скачивает один раз и держит в `config/code/art/cache`. Метаданные (хеш, размеры, кадры) сервер дописывает
в реестр сам, значения человека не трогает.

Анимированные GIF проигрываются: кадры складываются в атлас, анимация идёт сдвигом координат текстуры,
без повторной заливки. Большие картинки заливаются в видеокарту порциями, поэтому полотно в четыре
тысячи пикселей стороной не роняет кадр.

## Требования

- Minecraft 1.7.10, запуск на Java 8.
- CodeCore 1.1.0 или новее, зависимость `required-after:codecore`.
- Клиентская половина обязательна: сервер не пускает ванильный клиент, полотно без неё это пустой блок.

## Установка

| Файл | Куда |
|---|---|
| `CodeArt-0.1.0-server.jar` | `mods/` сервера |
| `CodeArt-0.1.0-client.jar` | `mods/` клиента, обязательно |
| `codeart-0.1.0-api.jar` | тем, кто пишет свой провайдер хранилища или мод с артами: компиляция |
| `codeart-0.1.0-dev.jar` | им же: deobf-версия для dev-запусков |

Ставится после CodeCore. Java 8 или 17 и 21 под lwjgl3ify, Forge 10.13.4.1614.

## Команды

| Команда | Право | Что делает |
|---|---|---|
| `/art list [страница]` | `codeart.view` | реестр артов с состоянием каждого |
| `/art info <имя>` | `codeart.view` | источник, размеры, хеш, кадры |
| `/art add <имя> <ширина> <высота> <источник>` | `codeart.admin` | скачать или найти картинку и зарегистрировать |
| `/art remove <имя>` | `codeart.admin` | снять арт с реестра |
| `/art reload` | `codeart.admin` | перечитать реестр с диска |
| `/art give <игрок> <имя> [число]` | `codeart.give` | выдать полотно предметом |

Полный список нод в `perms.md`.

## Настройки

- `config/code/art/art.toml`: потолки сервера. Размеры полотна и картинки, число кадров, разрешение
  источников http(s), список хостов, темп отдачи байтов клиентам.
- `config/code/art/client/art-client.toml`: как картинки выглядят у игрока. Бюджеты диска и памяти,
  потолки принимаемой картинки в мегабайтах и пикселях стороны, число одновременных загрузок, анимация,
  фильтрация.
- Главный файл линейки `config/code/config.toml`: провайдер хранилища в `[storage]` с перекрытием в
  `[storage.art]`. Встроен `json`, свой приносит мод через `ArtApi.registerStore`. Незнакомое имя
  выключает арты со строкой в лог, тихого отката на встроенное нет.

## Сборка

Нужен JDK 25, его версию задаёт `gradle/gradle-daemon-jvm.properties`. Wrapper скачает Gradle сам.

```
./gradlew build
```

Сначала соберите и опубликуйте соседей: `CodeSides` и `CodeCore` через `./gradlew
publishToMavenLocal`. В `build/libs` появятся `CodeArt-0.1.0-server.jar`, `CodeArt-0.1.0-client.jar`,
`codeart-0.1.0-api.jar`, `codeart-0.1.0-dev.jar` и универсальный `codeart-0.1.0.jar` для dev-запусков.
Универсальный jar раздавать нельзя: его не резали на стороны.

## Свой провайдер хранилища

Против `codeart-api` пишется реализация `ArtStore` и регистрируется на инициализации мода:

```java
ArtApi.registerStore(new SqlArtStore());
```

Активным становится провайдер, чьё имя стоит в `[storage.art] provider` главного файла. Хранилище
отвечает за реестр и байты картинок; манифест, передача и рендер остаются на модe. Своё провайдер
считает содержимое тем же sha256, что и встроенное: утилита `Hashes` ездит в api-джаре.
